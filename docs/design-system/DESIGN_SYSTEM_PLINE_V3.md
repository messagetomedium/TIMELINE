# ПЛАЙН — Design System v3 (Figma-first, composition-first)

**Дата:** 06.11.2026. **Источник:** [авторский файл Figma](https://www.figma.com/design/ZL9Fl89wbkuSpSAuqETPHr/TIMELINE---UIforGPT?node-id=0-1). **Состояние:** *композиционный контракт уже установлен владельцем; финальные визуальные токены и покомпонентная карта пока требуют просмотра макетов*. Не выдавать этот файл за полную измеренную спецификацию.

## 0. Необсуждаемый принцип композиции
Если в новом макете элемент стоит в другом месте, **перенести его в это место**. Композиция и размещение UI — предписание владельца, не просто настроение/стиль. Порядок смысловых блоков, их взаимное положение, визуальная иерархия, масштабность групп, форма и расположение папок/вкладок, место кнопок и заголовков — от Figma. Текущие React-компоненты служат функциональной основой, **не композиционным эталоном**.

Чертёжное несовершенство (неодинаковые отступы, неровная сетка, элементы на 1–5 px выше/ниже) **нормализовать**, не сохраняя ошибку один-в-один. Отличать случайный сдвиг от концептуально иной позиции элемента. При неоднозначности просить референс, а не вводить старую раскладку по умолчанию.

### Статус визуального анализа
Figma MCP ограничила доступ лимитом Starter после чтения дерева страниц и четырёх top-level frame ID; чтение screenshots и глубокой структуры **не прошло**. Поэтому нельзя надёжно назвать реальные цвета, названия шрифтов, точные размеры/отступы, раскладку элементов внутри экранов. Эти значения должны быть **измерены**, а не домыслены на основе старого TIMELINE v2.

## 2. Иерархия правил
1. Авторские макеты задают **расположение и композицию**.
2. Повторяющиеся реальные свойства Figma задают новые tokens (цвета, typography, radii, border, shadows).
3. Неровные интервалы приводятся к единому spacing scale без смены композиции.
4. Адаптивность/доступность дополняет, но не стирает авторский замысел.
5. Доменные контракты, хранение, безопасность, workflow и ограничения приложений — по `TIMELINE_MASTER_PLAN.md`.

## 3. Будущие токены: сначала измерить
Использовать семантические CSS custom properties, например:
```css
:root {
  /* Значения заполнить только после измерения соответствующих Figma-элементов. */
  --pline-surface: var(--measured-surface);
  --pline-text-primary: var(--measured-ink);
  --pline-accent: var(--measured-accent);
  --pline-border: var(--measured-border);
  --pline-radius-control: var(--measured-control-radius);
  --pline-radius-panel: var(--measured-panel-radius);
  --pline-space-unit: var(--measured-spacing-unit);
}
```
Этот код **не исполняемый CSS и не содержит фактических значений**; это список нужных категорий. Codex не должен добавлять неопределённые `--measured-*` в рабочую сборку.

**После Figma-аудита заполнить:** фон/поверхности/бордеры/текст/акценты/семантика; typography family/weights/size/leading/tracking с кириллицей; контур/толщина; radius; 8px/4px или реально обнаруженный rhythm; тени; иконки; hover/focus/disabled; размер hit-targets.

## 4. Экранная карта / FIGMA_LAYOUT_MAP (заполняется по доступным кадрам)
Для каждого фрейма составить таблицу:
`Фрейм → Блок → Положение (top/center/left/right/bottom) → Родительский контейнер → Соседство → Цель в React → Перенести относительно текущей версии? → Responsive rule`.

**Правило переноса:** перенести блок/контрол в новую зону композиции, даже если прежде он был в sidebar/header/modal. Перенос не создаёт новый backend endpoint и не отменяет доступное действие. Состояния popup/empty/error должны открываться относительно *нового* расположения origin control.

**Нормализация:** единые вертикальные линии, консистентные интервалы между одинаковыми рядами, общий базовый ритм карточек, выравнивание текста и контролов по логическим краям, адаптация для 1440px и узких окон. На 2560px следовать распределению из исходного фрейма; не просто масштабировать все пиксели линейно.

## 5. Структурные компоненты для проработки
- **Identity / старт:** название ПЛАЙН, tagline, вход, регистрация, модалка — композиция строго из фреймов.
- **Главная / портфель:** навигационные папки, список/содержимое, controls вида «карточки / таймлайн», сортировка и архив — расположение из Figma, логика текущего приложения.
- **Редактор проекта:** календарь, этапы, процессы, задачи, results gaps, чекпойнты, назначенные люди, inspector; если отдельного актуального фрейма нет — применять измеренный язык нового дизайна к существующей структуре **временно**, без произвольного перекомпонования частей, до утверждения.
- **Гость/команда:** только разрешённые controls/read-only scope, стили из подтверждённых токенов, безопасные fallback layouts.
- **Второстепенные экраны:** state variants, hover/focus, inline editing, tooltips; консистентные с выбранными новыми контуром и типографикой.

## 6. Критерии качества
- Авторская композиция сохранена, **все реально перемещённые в Figma элементы перемещены и в приложении**, а не перекрашены на прежних местах.
- Сетка и отступы приведены к одному ритму; компоненты больше не выглядят неаккуратно, но экран явно узнаётся как авторская Figma-композиция.
- Масштаб/прокрутка/выходные/раскрытия/виды живут в sessionStorage пользователя, **не синхронизируются**.
- Navigation, server mode, guest read-only, stages, results, dates, Undo/Redo и все рабочие кнопки сохранены.
- Клавиатурная доступность, контраст, крупная кириллица, читаемый текст на zoom, Safari/WebKit, адаптивная ширина без горизонтального скролла страницы (за исключением внутренней временной оси).
- Нет замены цветовых/типографических tokens догадками, даже если первоначальный скриншот недоступен.

## 7. Процесс реализации и выпуск
1. Достать visual refs/метаданные 4 Figma-фреймов и заполнить `FIGMA_LAYOUT_MAP` и фактические design tokens; отметить противоречащие детали для решения владельца.
2. Одним отдельным заданием Codex реализовать visual slice по новым композициям, без функционального переписывания.
3. PR + required checks, automatic Pages publication для проверки владельцем.
4. Рабочий `mediume.ru` не обновлять до согласованного общего release candidate, проверенной резервной копии/restore и отдельного запуска ручных сценариев.

**v2 архив:** `docs/design-system/DESIGN_SYSTEM_V2.md` хранить как историческое описание старого направления. Его палитра Klein Blue и прежняя композиция не являются базовыми токенами для ПЛАЙН v3.
