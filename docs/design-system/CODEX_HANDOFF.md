# Codex handoff — отдельная будущая задача Visual Identity

**Не исполнять автоматически.** Этот файл готовит контекст для Codex после явного отдельного задания владельца; наличие дизайн-системы в репозитории не разрешает начинать редизайн посреди функциональной версии.

## Короткий промпт для будущего запуска

Репозиторий messagetomedium/TIMELINE. Работай от актуального main после завершения уже назначенного этапа.

Прочитай AGENTS.md, docs/TIMELINE_MASTER_PLAN.md, docs/design-system/README.md, docs/design-system/DESIGN_SYSTEM_V2.md и docs/design-system/references/README.md. **Открой и изучи все пять WebP-файлов** из docs/design-system/references; это утверждённые пользователем визуальные референсы. Не ограничивайся описанием имён файлов.

Выполни исключительно визуальное обновление интерфейса на основе этих материалов: Klein/digital blue, чёрная массивная типографика, редкие оранжевые акценты, белое пространство, почти невесомые линии, папки и тонкий контур, глубокие скругления, деликатные цифровые градиенты/grain/glow. Применяй эффекты в крупных композициях; внутри таймлайна приоритет читабельности и захвата ручек.

Не копируй цвета референсов, которые не входят в палитру. Не добавляй отсутствующие функции по картинкам. Не меняй доменную модель, SegmentAxis, даты, процессы/задачи, каскады, результаты, checkpoint logic, постоянную Undo/Redo, хранилище или авторизацию.

Собери переиспользуемые CSS-токены и стили. Проверь читаемость, разные плотности задач, навигацию, F5, скролл, сворачиваемый инспектор, reflow и доступность. Без скриншотов и визуальных отчётов: владелец смотрит GitHub Pages.

Примени стандартную доставку: ветка → lint/build/typecheck и нужные тесты → PR → main → успешная публикация Pages. В конце перечисли изменённые UI-области, PR, коммит, результаты проверок и пять проверок для пользователя. На следующую функциональную версию не переходи.

## Не переписывать мастер-план ради редизайна

Дизайн-система — утверждённый визуальный источник для будущего авторизованного этапа. Функциональные решения остаются в docs/TIMELINE_MASTER_PLAN.md. Если выявлен конфликт с этим файлом, не менять поведение приложения: сохранить механику и описать визуальный компромисс.
