# Codex — будущий редизайн ПЛАЙН/TIMELINE по авторской композиции Figma

**Запускать только по отдельному явному поручению владельца.** Данный файл не разрешает редизайн в ходе V2.1B/V2.1C или других функциональных задач.

## Источник: новый Figma, не предыдущий дизайн
https://www.figma.com/design/ZL9Fl89wbkuSpSAuqETPHr/TIMELINE---UIforGPT?node-id=0-1

Прочитать `AGENTS.md`, `docs/design-system/README.md`, `docs/design-system/DESIGN_SYSTEM_PLINE_V3.md`, нужные разделы `docs/TIMELINE_MASTER_PLAN.md`. В `DESIGN_SYSTEM_V2.md` смотреть только историю, если явно нужно. Старые 5 WebP — не новые макеты.

**Главное указание владельца:** «если в макете какой-то элемент интерфейса на другом месте — значит его надо переместить; композицию брать с моих макетов». Не держаться за прежнее расположение React-компонентов. Не трактовать новые позиции как декоративные пожелания. Переносить контролы в соответствующие зоны, сохраняя их поведение и доступность.

**Макеты черновые:** исправить кривые расстояния, несогласованные края, мелкое выравнивание и ритм при помощи layout grid/spacing tokens. Но не переставлять части экрана по своему вкусу и не «исправлять» композицию обратно на старую.

## Перед кодом: обязательная проверка референса
1. Открыть реальные фреймы `14001:16`, `22025:6`, `22026:24`, `22026:66`; описать каждую зону и связать её с соответствующими React-компонентами, в том числе элементы, которые **переехали** относительно текущей UI.
2. Измерить реальные цветовые образцы, font-family/weights/sizes, отступы, геометрию рамок, радиусы и иконографику. Нельзя выбирать визуальные токены из старой системы v2 без проверки соответствия.
3. Обнаружить недостающие в макете интерактивные состояния (focus/hover/disabled/error/loading), сохранять текущую функциональность и размещать логично **в рамках новой композиции**; неоднозначности перечислить в PR.
4. Зафиксировать измеренное в `docs/design-system/DESIGN_SYSTEM_PLINE_V3.md`, `FIGMA_LAYOUT_MAP` и CSS variables до массовой стилизации.
5. При недоступном Figma не изобретать композицию; использовать подтверждённый экспорт/скриншоты от владельца или сообщить конкретный blocker.

## Область визуальной реализации
- Страница входа, главная/проекты, общий таймлайн, экран открытого проекта, боковые панели, календарные controls, редактирование, гостевой view, модалки и адаптивные состояния — по актуальным макетам.
- Компоненты, которых нет в макете, гармонизировать с подтверждёнными токенами, **не придумывать новые функции**.
- Визуальная переразметка может перемещать controls/секции, но **не меняет** смысл clicks, команды, dates, segmented axis, результатов, статусов, undo/redo, вкладок, прав и серверной модели.
- Личное представление (zoom/pan/weekends/grid/expanded/portfolio view) остаётся локальным, не становится shared command и не сбрасывается при realtime.
- На Mac сохранять жесты редактора/trackpad, keyboard focus и доступность.

## Доставка
Отдельная feature branch от актуального main, адресные lint/build/behavioral tests; полноценный PR checks перед merge. Публикация на Pages для осмотра; production VPS `mediume.ru`, SQL, SMTP/Gmail, бэкапы, домен и DNS не трогать. Только после большого релиз-кандидата, backup+restore и согласия владельца — единое обновление сервера.
