# ADR 0002: календарные даты и проверяемые документы

Статус: принято для доменной основы, 2026-10-29.

- Даты — брендированные строки `YYYY-MM-DD`, пролептический григорианский календарь, годы 0001–9999. Невозможные даты и timestamps отклоняются, а не нормализуются. `createdAt`/`updatedAt` — отдельные ISO timestamps, они не участвуют в расписании.
- Интервалы полуоткрытые: `[startDate, endDateExclusive)`, минимум один день. Смежные интервалы не конфликтуют. Последний день в UI вычисляется вычитанием одного календарного дня.
- Внутренний Date используется только с UTC getter/setter. Сложение календарных дней не зависит от DST или локального часового пояса. Годы 0001–0099 обрабатываются через setUTCFullYear, без преобразования в 1900-е.
- Добавление месяцев использует настоящий календарь и ограничивает число последним днём целевого месяца: 31 января + 1 месяц = 28/29 февраля. Это не обратимая операция: повторное сложение может отличаться от одного сложения на два месяца. Перемещения интервалов используют дни; snap по месячным границам будет отдельной операцией Slice 2.
- Неделя начинается с понедельника; выход за диапазон дат явно выбрасывает RangeError. Zoom и шаг сетки — независимые поля, ни одно не меняет расписание при валидации.
- Все ID — проверенные RFC UUID, нормализованные к нижнему регистру, с отдельными брендами сущностей. Номера позиций и индексы массивов ID не заменяют. Будущие операции создания будут применять crypto.randomUUID и проверять результат схемой.
- Runtime-схемы строгие: неизвестные поля запрещены, parse возвращает readonly/frozen сущности и массивы. `ProjectDocument` проверяет уникальность UUID, принадлежность проекту, ссылки, принадлежность дорожек, включение задач в процесс, пересечения в одной дорожке, ссылки назначений и раскрытий. Проверка не двигает даты и не исправляет пользовательские данные молча.
- Процесс может быть длиннее детей. Даты проекта хранят явный диапазон; требование помещать все процессы/этапы внутрь диапазона проекта не вводится без отдельного решения.
- `Lane.kind` различает верхнюю process-дорожку (`processId: null`) и task-дорожку с обязательным родителем. `Assignment.targetType` определяет бренд targetId. Несколько назначений на цель и неназначенная роль без personId допустимы; роль находится на назначении.
- Временно `expandedAssigneeGroupIds` ссылается на AssignmentId группы. Конкретные группировки панели исполнителей будут определены при Slice 4; явное решение предотвратит свободные строки без ссылочной целостности.
- Dependency и серверные сущности не добавлены в рабочую схему: они зарезервированы архитектурой, поведение и API будут проектироваться в соответствующем срезе. Ранняя модель не должна создавать ложное впечатление реализованного планировщика или безопасности.
