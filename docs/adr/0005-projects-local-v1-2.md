# ADR 0005: проекты, портфель и локальные агрегаты

Принято 2026-10-30. Единый документ `docs/specs/TIMELINE_V1_2_SINGLE_TZ.md` задаёт V1.2 и переопределяет порядок прежнего roadmap. Следующие этапы не выполняются. База реализации — main 8535428; до изменений прошли lint/build, 90 unit и 20 e2e тестов.

## Один источник данных

Вместо одного useState(demo) App загружает snapshot WorkspaceService. Карточки, строки портфеля и активный редактор получают одни ProjectDocument. Временная копия во время жеста — preview, а не второй репозиторий. После успешной операции UI перечитывает сохранённый snapshot. При ошибке записи подтверждённые документы не заменяются неподтверждённым результатом.

Все изменения проходят через WorkspaceService и чистые функции createEmptyProject/cloneProject/shiftProject/addWork, затем через Zod и repository. Существующие операции V1.1 остаются чистыми и сохраняются через тот же service.commit. React не импортирует Dexie и не обращается к таблицам. Композиция адаптера находится в main.tsx; сервер не добавлен.

## Сохранение

Dexie database `timeline-workspace`, version 1: documents, preferences, metadata. Проект хранится одним агрегатом. save проверяет expectedRevision и следующую revision в общей rw-транзакции; create-only использует null. delete тоже проверяет ревизию. При конфликте UI загружает актуальный snapshot, включая удаление проекта; никакого last-write-wins.

Seed + initialized сохраняются в транзакции. Только самая первая пустая база получает один пример. При наличии документов, даже без metadata, они сохраняются; удаление последнего проекта не возвращает демо. Ошибки чтения/версии не исправляются сбросом базы. Предыдущий V1.1 не имел постоянного хранилища: version 1 — начальная схема, будущие миграции будут явными.

Workspace prefs хранят mode и отдельную camera/step/weekends портфеля. `editor:<id>` хранит ViewPreferences внутреннего редактора без изменения schedule revision. Load/export/clone накладывают актуальный сохранённый view на документ. Удаление проекта удаляет и его view. Изменения камеры во время pointermove не сохраняются: view фиксируется после окончания/отмены жеста, а документ — только после commit. Статус записи охватывает и preferences. При первом посещении редактора без сохранённого view сохраняется логика фокуса V1.1; при повторном открытии приоритет у сохранённой камеры.

## Портфель и операции

Реальная отдельная сцена использует существующие CalendarCell, CalendarRuler, TimeGrid и TimelineCamera. Gutter 240 px — отдельная колонка; ряды упорядочены по sortIndex/UUID. Диапазон строки объединяет явные границы, работы и маркеры; для маркера end-exclusive = date + 1 день. Цвет акцента определяется стабильным ID, не новым полем схемы. Fit вычисляется по всем документам и допускает масштаб меньше рабочего минимума для многолетнего диапазона; обычный рабочий zoom сохраняет прежние пределы.

ShiftProject вычисляет одну дельту от привязанного начала полосы. Проектные даты/якорь, маркеры, процессы и задачи сдвигаются ровно один раз. Полоса не имеет resize-контролов; соседние проекты на разных строках не мешают переносу. До pointerup изменяется только preview; Esc/cancel/blur ничего не записывают. Ручка подавляет последующий click/open, тело полосы не переносит проект.

Deep clone создаёт новые ID проекта, маркеров, областей этапов, дорожек, процессов, задач и назначений; переписывает все ссылки и expansion IDs. Person IDs сохраняются, объекты отдельные. Глобального живого справочника пока нет; будущая общая таблица людей потребует миграции/конфликтной политики. Метаданные клона новые, revision=0. updatedAt существующего проекта меняется только в сервисе при commit; pure shift не читает часы.

Новый проект не содержит скрытых примеров. Формы процесса/задачи используют явную выбранную или новую дорожку; существующие элементы не переупаковываются. Ввод окончания включительный, конвертируется в endDateExclusive. Новая задача может расширить родителя атомарно. Полная система удаления/undo/вертикального переноса остаётся V1.3.

## JSON и навигация

Backup envelope имеет format/version/exportedAt/documents/preferences. До показа подтверждения валидируются все вложенные ссылки и уникальность проектных ID. В insertBatch коллизии проверяются заново в транзакции: ошибка поздней записи откатывает весь пакет и preferences. При конфликте доступен импорт всего набора как копий или отмена; overwrite не предоставляется. People IDs между документами не считаются коллизиями.

Hash routes `#/projects` / `#/projects/:id` выбраны для GitHub Pages без серверного fallback. Browser Back и refresh восстанавливают экран; отсутствующий ID показывает нормальное состояние. После удаления активного проекта маршрут возвращается к списку. Внутренний редактор не получает переключатель карточек/портфеля.

## Проверка и границы

Unit/integration проверяют всё дерево клона, полные наборы дат, DST-математику через прежние тесты, транзакционные ревизии/rollback, reopen, seed, prefs и импорт. Playwright проверяет реальные жесты, создание/наполнение, оба вида, копию, F5, Back, удаление/импорт и все регрессии V1.1. Скриншоты V1.2 получены из созданных через UI проектов, не из статических макетов. Пользовательская база нигде не очищается ради тестов.

Нет Undo/Redo, Shift-групп, вертикального переноса существующих работ, полного инспектора/ассайнинга, PDF, auth/server/AI. Хранилище локально данному origin и браузеру, без обещаний синхронизации.
