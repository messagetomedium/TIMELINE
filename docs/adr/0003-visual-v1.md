# ADR 0003: визуальный V1 вместо стартовой сводки

Принято 2026-10-29 по новому заданию `docs/specs/04_CODEX_FIRST_PROMPT.md`.

## Объём

Новый комплект спецификаций приоритетнее прежних `ARCHITECTURE.md`, `CODEX_SPEC.md` и решений ADR 0001 о начальном экране. В этой ветке выполняется **V1 из нового плана**, а не весь V1–V7. `00_START_HERE.md` был упомянут в задании, но не приложен; остальные четыре документа сохранены без изменений. PDF-референс помещён в `docs/reference/production-timeline.pdf`.

Сразу открывается редактируемый производственный пример: календарный год с 2026-09-01, четыре этапа, восемь процессов, 32 задачи, восемь людей и 40 назначений. UUID/даты фиксированы. Список проектов остаётся в шапке, а старая текстовая сводка и малая фикстура сохранены в исходниках для совместимости. При перезагрузке демо сбрасывается; об этом явно сказано в шапке и инспекторе. Не создаются IndexedDB, localStorage или серверное соединение.

## Модель и координаты

StageMarker остаётся датированной границей. Новая StageBand ссылается на левую и правую границы; соседние области делят ID общей границы. Это аддитивное расширение DTO v1: старые документы получают `stageBands: []`. Постоянных данных и миграций базы ещё нет. Границы не могут пересекать соседние этапы, процессы от них не зависят.

`domain/timeline.ts` — единственный источник `xForDate`, `dateAtX`, ширины, zoom и snap. Отрицательные координаты и дробные масштабы учитываются. Шаги 1/2/3 дня отсчитываются от 1970-01-01, недели/две недели — от понедельника 1970-01-05. Месяцы привязаны к первым числам реального календаря; при равенстве расстояний nearest выбирает следующую границу. Перемещение с недельным шагом привязывает начало к понедельнику, сохраняя относительные смещения детей. Поэтому сдвиг курсора на семь дней для исходной даты посреди недели не обязательно означает ровно семь дней изменения.

Начальный zoom помещает год по ширине сцены. При очень широком представлении подписи календаря укрупняются до недельных для читаемости, но геометрия grid/snap остаётся выбранной пользователем. `+`/`−` удерживают календарную координату центра viewport; изменение размера окна сохраняет камеру. Нижний блок использует точно ту же камеру, независимо от своих строк. Вертикальное перемещение использует scrollTop производственной секции; нижняя зона закреплена и прокручивается по вертикали отдельно.

`layoutTimeline` вычисляет строки из явного sortIndex и ID без автоупаковки. Для нескольких последовательных процессов на общей дорожке её раскрытая высота — максимум дочерних групп, а не сумма: непересекающиеся группы используют общие уровни под заголовками.

## Действия

V1 использует небольшой чистый `applyTimelineCommand`, общий для preview и commit: rename, move, resize, move stage. Это ещё не полноценный CommandBus с историей. Полный документ проверяется runtime-схемой до применения: недопустимые коллизии, пересечение границ этапов и обрезка детей отклоняются, а не исправляются скрытно. При переносе процесса дети сдвигаются один раз; при изменении только границы дети не двигаются. Перенос/расширение задачи может увеличить родителя, сокращение задачи его не уменьшает. Ревизия проекта увеличивается только при подтверждении команды.

Pointer Events с захватом на стабильной поверхности: исходный документ фиксируется на pointerdown, pointermove создаёт временный проверенный документ, pointerup применяет один результат. Esc, pointercancel, потеря захвата и blur отменяют preview. Обычный текст не запускает drag; для перемещения есть отдельная ручка, для resize — отдельные края. Некорректный preview подсвечивает выбранную полосу красным и объясняет причину; неподтверждённые даты не попадают в документ.

Инспектор пока меняет только название (Enter/blur), остальные свойства — read-only. На полосе Enter подтверждает inline-имя, Escape отменяет. Люди и назначения read-only, hover работает в обе стороны. Несколько назначений одного человека могут накладываться в его строке занятости — это отображение нагрузки, не перемещение дорожек или изменение дат задач.
