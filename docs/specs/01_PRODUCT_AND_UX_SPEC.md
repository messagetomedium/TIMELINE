# TIMELINE — продуктовое и UX-техническое задание v2
Дата: 29.10.2026. Статус: требования из трёх раундов брифа + явно обозначенные технические предположения.

## 0. Продуктовая цель и главное отличие

Создать настольный браузерный визуальный редактор производственных планов. Вдохновение: предоставленный заказчиком одностраничный PDF «Таймлайн производства» со стадиями производства, параллельно/последовательно расположенными рабочими блоками и занятостью исполнителей снизу. Удобство и свобода редактирования должны ощущаться как в Figma: просторная панорамируемая рабочая область, масштаб, перетаскивание за ручку, изменение размера за края, прямое редактирование текста.

Это НЕ Trello, НЕ таблица, НЕ список задач, НЕ стандартный Gantt с обязательным столбцом названий слева. Графическая временная сцена — главный и самый большой экран приложения. Временная сетка, верхний производственный блок и нижний блок исполнителей разделяют одну горизонтальную ось дат.

**Рабочее правило:** красивый список проектов, таблица задач или текстовая сводка демо НЕ считаются редактором и не принимаются вместо временной сцены.

## 1. Экраны и первичная навигация

- `Главная / Редактор`: при первом запуске локальной тестовой версии пользователь сразу попадает в редактируемый демонстрационный производственный таймлайн (данные локальные). Это нужно, чтобы оценить интерфейс с первого открытия. После создания собственных проектов открывается последний активный проект. Отдельная кнопка `Проекты` выводит в список проектов.
- `Проекты`: создать пустой проект; открыть; переименовать; создать полную копию проекта; удалить с подтверждением; перейти к сводному таймлайну всех проектов. Новый пустой проект действительно пуст: никаких скрытых демо-заданий.
- `Проектный таймлайн`: основной рабочий экран в полноразмерной рабочей области.
- `Все проекты`: сводный таймлайн, на котором вместо процессов расположены проекты. Перемещение проекта смещает все его этапы, процессы и задачи.
- Никакого входа, регистрации, AI-чата или настроек сервера в версии 1.0.

### 1.1 Предлагаемая композиция основного экрана

```text
┌───────────────────────────────────────────────────────────────────────────────┐
│ Проекты  /  [название проекта ▾]                         [PDF] [⋯]           │
├───────────────────────────────────────────────────────────────┬───────────────┤
│           ГОРИЗОНТАЛЬНАЯ ВРЕМЕННАЯ ОСЬ  (даты)                │   ПРАВАЯ      │
│    ЭТАПЫ: подписи, даты, ─│─ линии и круглые ручки сверху     │   ПАНЕЛЬ      │
│                                                               │   ДЕТАЛЕЙ     │
│ ┌──── процесс A ───────────────┐   ┌──── процесс B ─────┐    │               │
│ │ [задача 1 ───] [задача 3 ─] │   │ [задача ...]       │    │ название      │
│ │     [задача 2 ─────────]    │   └────────────────────┘    │ описание      │
│ └──────────────────────────────┘                              │ даты          │
│                                                               │ статус        │
│──────────── ЗАНЯТОСТЬ ИСПОЛНИТЕЛЕЙ ──────────────────────────│ исполнитель   │
│  лид процесса A      [──────────────]                         │ цвет процесса │
│    художник — Анна       [──────]                             │ результат     │
│    художник — Иван              [──────]                      │               │
│                                                               │               │
│             [↶] [↷] [−] [+] [шаг сетки ▾] [выходные]         │               │
└───────────────────────────────────────────────────────────────┴───────────────┘
```

*Схема — структурная, не пиксельный дизайн; ширины и высоты согласовать по фактическому браузеру. Обе секции используют ОДНУ и ту же шкалу времени и общую горизонтальную прокрутку/панорамирование. Правая панель может открываться/закрываться и не должна уменьшать сцену до узкого списка.*

- Рабочая область занимает всю доступную высоту экрана и максимум ширины; убрать текущий ограничивающий `main { width: min(1120px, 90vw) }` из режима редактора и текущий текстовый `ProjectSummary` как основной экран.
- Наверху — компактная шапка и календарный ruler с числами/днями/неделями в зависимости от масштаба.
- Ниже — полоса визуальных этапов и границ; далее — процессы и вложенные задачи; ниже — отдельная зона загрузки исполнителей; поверх внизу — небольшая плавающая панель инструментов.
- Детали выбранного элемента открываются справа, без перехода на другую страницу.
- Интерфейс на русском языке.

## 2. Предметная модель и смысловая структура

### 2.1 Этап

Этап — **не родитель и не папка**; он только отмечает временную область на общем календаре. Это верхняя полоса с названием (например, «Препродакшн») и датированными вертикальными границами. Каждая граница рисуется как тонкая вертикальная линия через производственную рабочую зону с круглым маркером вверху. Изменение даты в надписи переносит линию точно по сетке; перетаскивание кружка меняет дату и обновляет подпись. Соседние этапы могут делить одну границу. Этап не «владеет» процессами и не двигает их при изменении своей границы. При перемещении ВСЕГО проекта границы этапов сдвигаются вместе со всем содержимым.

### 2.2 Процесс

Процесс — горизонтальный цветной блок-контейнер, имеющий собственные даты, название, цвет (назначается вручную через правую панель), статус и лид-исполнителя. Может располагаться на одной линии с другими последовательными процессами или на отдельной линии для параллельной работы. Свернутый процесс выглядит как одна длинная цветная плашка. При раскрытии задачи появляются **внутри/сразу под ним в его вертикальном контексте**, расширяя высоту области и сдвигая расположенные ниже строки. Можно раскрыть сколько угодно процессов одновременно.

Перенос процесса на +N календарных дней переносит все вложенные задачи ровно на +N дней, сохраняя их взаимные интервалы и строки. Если растянуть задачу левее/правее контейнера, временные границы контейнера автоматически расширяются. Если сократить процесс так, что задача вышла бы за границу, запрещать такой размер/ограничивать его границами задач; задачи самовольно не обрезать.

### 2.3 Задача

Задача — горизонтальная цветная плашка ВНУТРИ процесса. На плашке только название, не выводить повторные даты или большие карточки. Срок читается с сетки. Цвет по умолчанию — производный оттенок цвета процесса. У задачи свои даты, статус, описание, назначение исполнителей и строка.

### 2.4 Строки (дорожки)

Строка имеет **производственный смысл**, пользователь определяет её сам:
- Работа, идущая последовательно за другой, размещается на той же строке справа от неё.
- Работа, идущая параллельно, размещается на отдельной строке выше/ниже.
- Вертикальный перенос задачи меняет выбранную строку. Можно создавать и менять порядок строк.
- Нельзя случайно автоматически переупаковывать задачи по строкам «для красоты».
- Нельзя накладывать блоки с пересекающимися датами в одной строке: показать визуальную подсказку о конфликте, предложить другую строку; не сдвигать соседей автоматически.
- У процессов есть собственные строки верхнего уровня, у задач — строки внутри конкретного процесса. Внешняя вложенность только одна: `Процесс → Задачи`; этап — визуальная область, а не контейнер.

## 3. Жесты и курсоры (обязательные)

| Действие | Поведение |
| --- | --- |
| Одиночный клик по процессу | Выделение, открытие правой панели и раскрытие задач; повторный клик допускает сворачивание по отдельному шеврону, чтобы было легко выделять процесс без случайного закрытия. |
| Клик по задаче | Выделение и её свойства справа, процесс остаётся раскрытым. |
| Двойной клик по названию | Inline-поле редактирования внутри плашки; Enter — сохранить, Esc — отменить; не начинать перетаскивание. |
| Захват небольшого маркера слева-сверху плашки | Перетаскивание блока по дате и при необходимости по строкам. Захват за обычный текст не переносит блок. |
| Захват левого/правого края | Изменение начала/окончания по временной сетке, с предварительным контуром. |
| Shift + клики | Множественное выделение процессов/задач; перетаскивание группы на одинаковое календарное смещение; один пункт истории. Смешанные родитель+ребёнок не должны сдвигать ребёнка два раза. |
| Колесо мыши зажато (middle drag) | Панорамирование рабочей области; не меняет данные. |
| Левая кнопка зажата на ПУСТОМ месте | Панорамирование; не создавать случайно задачу и не менять сроки. |
| `+` / `−` в нижней панели | Масштаб картинки/координат в пикселях; не изменяет реальные даты. |
| Выбор шага календаря | Меняет визуальные клетки И точку прилипания в ходе перетаскивания/растягивания. |
| `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z` | Отмена / повтор последнего пользовательского изменения; кнопки ↶ ↷ на панели. Не перехватывать комбинации, когда курсор редактирует текст. |
| Наведение на задачу/процесс | Подсвечивает связанного исполнителя (или группу) в нижней зоне, без открытия модалки. |
| Захват круглого маркера границы этапа | Перенос вертикальной линии этапа и изменение его даты. |

Вместо переносов по обычной плашке должна быть **явная маленькая ручка** с курсором `grab/grabbing`. По краям — `ew-resize`. В режиме перемещения видна полупрозрачная предварительная позиция; commit только после mouseup/pointerup. При отмене через Esc данные не изменяются. Использовать Pointer Events и pointer capture с обработкой `pointercancel`, blur окна и потери захвата.

## 4. Календарь, масштаб и сетка

- Горизонтальная координата одна и та же у этапов, процессов, задач, нижних исполнителей и маркера сегодняшнего дня.
- Шаг сетки/прилипания: `1 день`, `2 дня`, `3 дня`, `1 неделя`, `2 недели`, `1 календарный месяц`.
- Масштаб `+`/`−` независим от шага; можно показать неделю очень широко и месяц очень компактно. Zoom желательно центрировать в точке указателя или в центре viewport. Даты не изменяются.
- При переносах с шагом в 1 день задача прилипает к суткам; на шаге недель — к недельным границам; месяц привязан к началу настоящего календарного месяца (не 30 дней).
- Отдельная кнопка `Выходные` включает/выключает **очень бледные зелёные вертикальные полосы** суббот и воскресений; это только отображение, выходные не вырезаются из длительности задач.
- **Сегодня** — вертикальная визуально отдельная линия через рабочую область, подписана актуальной датой; следует за календарём, не является этапом, обновляется при смене дня.
- Панорамирование не меняет даты и не должно разрывать выравнивание верхней и нижней шкал.
- Сетка полупрозрачная, даты сверху; читаемость обязана сохраняться на широких диапазонах.

## 5. Правая панель

Панель открывается при выборе объекта. В первый релиз включить:
- тип объекта; название (редактируется); начало и конец (прямой ввод даты); статус: `Не начато`, `В работе`, `Согласование`, `Пауза`, `Готово`, `Закрыта`;
- свободное описание и поле результата; у процесса — выбор цвета; ответственный лид процесса; исполнители задачи;
- кнопки `Добавить задачу`, `Дублировать`, `Удалить` с подтверждением критических удалений;
- изменения сразу отражаются на временной сцене; нет отдельной обязательной кнопки `Сохранить`.

Никаких процентов прогресса, тяжёлых форм CRM, чатов, отчётов и календарей справа в первой версии.

## 6. Нижняя шкала исполнителей

Отдельная вертикально сворачиваемая секция **под процессами**, но в том же календарном пространстве.
- Группа — лидер/роль процесса; группу можно раскрыть для просмотра людей задач процесса.
- Строка показывает `Роль — Имя Фамилия`, если имя внесено; иначе только роль. Человек может участвовать в разных проектах и разных ролях.
- Каждое назначение рисуется полосой на датах соответствующей задачи или процесса. Не использовать не связанные с датами списки людей.
- При наведении курсора на процесс/задачу подсвечиваются соответствующие исполнители и их полосы. Возможна обратная подсветка.
- В правой панели поле исполнителя с автодополнением по уже существующей базе, фильтрация с первых набранных букв. Если человек отсутствует — создать запись и привязать. Допустить несколько исполнителей одной задачи.
- Нижняя зона может меняться по высоте, но горизонтальная временная система остаётся общей с верхней.

## 7. Проекты и портфолио

- `Новый проект` создаёт чистое рабочее пространство с датами и пустыми дорожками; пользователь создаёт этапы, процессы и задачи сам.
- `Дублировать проект` делает независимую полную копию: процессы, задачи, строки, разделители этапов, назначения, раскладку и настройки вида. Все внутренние ID новые, связи корректно переназначены. Общая библиотека людей может использовать те же записи людей.
- `Все проекты`: большой горизонтальный таймлайн, где на полосах вместо процессов видны проекты. При переносе блока проекта на N дней **все даты проекта** (его собственные границы, этапы, процессы и вложенные задачи) сдвигаются на N дней ровно один раз.
- На мобильном устройстве: просмотр проектов и смена статусов; полнофункциональный touch-редактор пока не обязателен.

## 8. Сохранение и undo

Локальная версия работает без логина, без сервера и без Supabase. После каждого завершённого действия данные надёжно сохраняются в браузере через IndexedDB. Перезагрузка страницы не должна сбрасывать работу. Предусмотреть экспорт/импорт JSON для резервной копии (это отдельно от PDF). `Undo/Redo` только в рамках текущего сеанса, без сложной истории и аудита. Один drag = один шаг истории. Все изменения проходят через один механизм команд — будущая сеть и ChatGPT смогут использовать те же смысловые операции.

## 9. PDF

Одна команда `Экспорт в PDF`. Результат отражает **текущее настроенное представление рабочей зоны на момент экспорта**: выбранный проект, видимый диапазон дат/панорамирование/масштаб, раскрытые процессы, выбранную сетку, цвета, линии этапов, сегодняшнюю линию (если попадает в диапазон), включение выходных и текущее состояние секции исполнителей. Инспектор, шапка, ручки, выделение, курсор, плавающая панель и прочие редакторские элементы в PDF не входят. Формат — одна страница с соотношением сторон области экспорта, достаточным разрешением и читаемыми русскими шрифтами. Не раскрывать все процессы принудительно и не делать «подогнать весь проект» вместо текущего вида.

Предусмотреть явную команду «Предпросмотр PDF»; результат должен совпадать с содержимым на экране, за вычетом контролов. При невозможности обеспечить масштаб без потери читабельности предупреждать, а не обрезать молча.

## 10. Вторая версия (НЕ делать в текущем первом релизе)

- 5–20 одновременных участников, серверная база, синхронизация и права;
- роли: администратор (полные права) и гость (просмотр только выданного проекта);
- доступ гостя по безопасной ссылке-приглашению к конкретному проекту, а не публичный доступ ко всему хранилищу;
- авторизация по email+паролю и предпочтительно Google Sign-in;
- временная блокировка только редактируемого элемента, остальные элементы доступны другим пользователям;
- ChatGPT из обычного чата: чтение, анализ, создание плана, изменение задач/дат, назначение исполнителей; **каждая предложенная серия правок перед применением показывается на подтверждение**;
- полноценные зависимости задач и автоматическое перепланирование — позже, не путать с перемещением выделенных элементов с Shift.

## 11. Формальные критерии приёмки первой работающей версии

1. При запуске виден большой **временной редактор с конкретными полосами**, датами и нижней зоной исполнителей, а не текстовый список.
2. Верхний и нижний блоки совмещены по одной горизонтальной оси, после pan и zoom они не разъезжаются.
3. Можно раскрыть два или более процесса одновременно; дочерние задачи не исчезают при выборе соседнего.
4. Двойной клик меняет название прямо на полосе; обычный клик открывает правую панель.
5. Перемещение происходит только за маркер; изменение срока — за левый/правый край.
6. Перемещение процесса сдвигает все задачи ровно один раз, изменение границы задачи может расширить процесс.
7. Две задачи могут идти на одной строке последовательно; параллельные — на разных; при совпадении сроков в одной строке отображается конфликт, а не хаотический перенос.
8. Шаг сетки не равен визуальному масштабу; изменение масштаба не редактирует даты.
9. Выходные и сегодняшняя линия отображаются корректно по реальному календарю.
10. Этапы существуют как вертикальные разделители, их положение и подписанная дата меняются согласованно.
11. Наведение на блок подсвечивает соответствующих исполнителей снизу.
12. Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z отменяют/повторяют завершённые изменения; после перезагрузки данные сохраняются.
13. Копирование проекта сохраняет содержание, но не связывает копию с оригиналом.
14. Общий таймлайн переносит целый проект со всеми его датами.
15. PDF визуально отражает текущую рабочую сцену, а не список задач.
