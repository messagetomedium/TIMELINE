# TIMELINE — план разработки для Codex (по проверяемым вертикальным срезам)
Дата: 29.10.2026. Исполнять **в существующем** `messagetomedium/TIMELINE`, не создавать новый репозиторий.

## Обязательное правило

В каждом цикле результатом является видимое, работающее поведение в браузере, а не новые архитектурные документы и пустые компоненты. `Документация + тесты без рабочего редактора` — не завершение этапа. После каждого этапа — скриншот, воспроизводимые жесты, результат сборки и тестов. Если не реализована существенная часть этапа, перечислить конкретные пробелы, не выдавать этап за выполненный.

### Этап V1 — «Настоящая сцена вместо текстовой сводки» — сделать первым

Заменить основной экран `ProjectSummary` на полноэкранный `TimelineWorkspace`. Загрузить насыщенный демонстрационный производственный план, сопоставимый по структуре с PDF: 4 этапа, 8+ процессов, 25+ задач, разные строки, подписи, рабочая загрузка исполнителей внизу. Пока источник данных может быть in-memory demo. Пользователь должен СРАЗУ увидеть дату, полосы, этапы, нижнюю секцию, правый inspector и панель инструментов; никаких экранов логина или пустого welcome screen вместо сцены.

Обязательно рабочие операции этого этапа: pan средней кнопкой мыши/ЛКМ на пустом фоне; zoom +/- независимо от шага сетки; переключение календарного шага; weekend toggle; current-day line; раскрытие нескольких процессов; клик с выбором и инспектором; двойной клик с inline-редактированием названия; перемещение за выделенную ручку хотя бы одного процесса/задачи; ресайз по обоим краям; перенос кружка одного stage divider. В нижней части должны быть на датах полосы исполнителей (первоначально read-only) с подсветкой по наведению.

**Acceptance V1:** открытый URL сразу даёт скриншот полноценного временного редактора, а не списка. Все перечисленные операции демонстрируются в браузере и имеют правильную геометрию; обновление данных in-memory достаточно, локальное сохранение отдельным этапом. Линии, полосы и нижняя часть совпадают по временной оси после pan и zoom.

### Этап V2 — «Безопасное манипулирование объектами»

Добавить единый command layer и инварианты, если ещё не сделаны: перенос процесса со всеми задачами (только один раз); drag между дорожками; запрет коллизий внутри одной дорожки; растяжение задачи с автоматическим расширением процесса; запрет обрезки дочерних задач при сжатии процесса; Shift multi-select и групповой перенос; маркер этапа ↔ дата; undo/redo кнопками и клавиатурой, один drag — один undo-step; подтверждение удаления.

**Acceptance V2:** сценарии с двумя параллельными и тремя последовательными задачами работают без самовольной вертикальной перестановки. Процесс сдвигается на 7 дней, все дети — тоже на 7 (не 14); `Undo` полностью возвращает состояние.

### Этап V3 — «Правая панель и исполнители»

Добавить полный базовый инспектор (название, описание, даты, результат, статус, процессный цвет, исполнители). Роли + имена, глобальный справочник людей, autocomplete по буквам, назначение одного/нескольких исполнителей задач, процессные лиды. Нижняя зона исполнителей с раскрываемыми группами: лид → люди отдельных задач; полосы по времени; hover с двухсторонней подсветкой. Редактирование даты справа меняет bar, и наоборот.

**Acceptance V3:** назначить художника по имени из существующей базы, открыть его группу внизу, навести на соответствующую задачу, увидеть подсветку; поменять дату — блок немедленно переместился согласно календарю.

### Этап V4 — «Настоящие локальные проекты»

Подключить IndexedDB/Dexie через `ProjectRepository`. Создание пустого проекта, переименование, удаление, копирование со всеми вложениями и сохранением раскладки; список проектов и переключатель в шапке. Первый запуск с одним редактируемым образцом для демонстрации; повторная инициализация не затирает/не возвращает пользовательские данные. Автосохранение после commit-команд; JSON backup/import; локальные migrations. Состояние раскрытия, выбранного шага, zoom и панорамирования сохранять по проекту как представление. Undo пока только в сессии.

**Acceptance V4:** после реального drag и изменения текста обновить страницу — данные сохранились. Скопировать проект, изменить одну задачу только в копии — исходник не изменился. Пустой проект остаётся пустым.

### Этап V5 — «Общий таймлайн проектов»

Режим портфолио: те же ось, панорамирование, масштаб и календарный шаг, но вместо процессов — проекты. На примере трёх проектов выполнить перенос целого проекта на +1 месяц/фиксированное календарное число дней с корректным переносом всех его этапов, процессов и задач. Из портфолио открывается конкретный проект.

**Acceptance V5:** после переноса проекта сравнить даты нескольких стадий/процессов/задач до и после, все сдвинуты ровно один раз; изменения видны в обычном проектном редакторе.

### Этап V6 — «Экспорт PDF текущей сцены»

Внедрить экспорт именно настроенного вида (активное окно календаря, шаг, zoom, раскрытые строки, видимые исполнители, выходные, этапы). Инструменты, выделение и правую панель исключить. Один PDF лист под соотношение текущей рабочей зоны, русские шрифты читаемы. Предпросмотр до скачивания.

**Acceptance V6:** развернуть 2 процесса, скрыть секцию исполнителей, перенести viewport на другой месяц, переключить сетку, экспортировать: PDF показывает именно это, не глобальную таблицу со всеми задачами.

### Этап V7 — «Доводка, тестирование и мобильный просмотр»

Нагрузочное тестирование на проекте масштаба PDF, визуальная QA на 1440×900 и 1920×1080, улучшения доступности и производительности; responsive мобильный просмотр таймлайнов/проектов и редактирование статусов в простом списке или карточке (без full touch-редактора). Проверки экспорта и сохранения, отлов конфликтов жестов. Документация по локальному развертыванию/GitHub Pages.

**Acceptance V7:** стабильная работа на полноценном тестовом проекте, нет потери данных, нет ошибок в браузерной консоли, мобильные страницы доступны без горизонтально обрезанных контролов.

### Отдельная следующая фаза (НЕ включать в v1)

Многопользовательский сервер: Supabase/PostgreSQL, ограничение прав администратора и гостя, email/password+Google OAuth, приглашения в конкретный проект, real-time синхронизация, временные блокировки редактируемых элементов с TTL. Позже — ChatGPT/MCP с чтением и подтверждаемыми предложениями изменений. Не смешивать это с V1–V7.

## Инженерная дисциплина для каждой итерации

1. До изменений прочитать ТЗ/архитектуру/текущий код; назвать в ответе файлы, которые реально будут изменены. Не предлагать снова переписать стек.
2. Реализовать один вертикальный срез, закончить запланированные жесты. Не заменять настоящее поведение неработающими кнопками.
3. Проверить `npm run lint`, `npm run build`, `npm run test`, `npm run test:e2e` (если тесты требуют Chromium, документировать способ запуска). Добавить тесты для новых операций.
4. Сделать Playwright-скриншот **реальной** рабочей области после загрузки демопроекта, на ширине 1440 px (и, при возможности, 1920 px). Оценить плотность и композицию относительно PDF. Проверить панорамирование, раскрытие нескольких процессов, положение подписей и отсутствие наложений.
5. В отчёте показать: какие функции действительно работают, какие НЕ работают, какие тесты были запущены, какой URL Pages ожидается и подтверждена ли публикация.
6. Не очищать хранилище реальных проектов, не менять исходные даты без пользовательской команды, не перезаписывать CI/конфигурацию без причины.
7. Для изменённых файлов использовать отдельную ветку и PR, если доступны; до принятия visual V1 не удалять предыдущий код и не принимать автоматическую подмену основной сцены страницами-заглушками.

## Анти-паттерны — запрещено

- Реализовать очередной `ProjectSummary` с текстовыми карточками и считать его таймлайном.
- Показывать процессы как вертикальный список с датами справа вместо горизонтальных полос по оси времени.
- Использовать только CSS flex/grid без реальной date→x-геометрии.
- Двигать блок при drag за любую область (должна быть отдельная ручка).
- Считать Zoom настройкой шага календаря или наоборот.
- В одной строке автоматически переставлять задачи, хотя пользователь задал последовательность.
- Отдельно скроллить/масштабировать зону исполнителей, из-за чего даты перестают совпадать.
- На каждом pointermove записывать данные и новую позицию в undo.
- Добавлять сервер, OAuth, AI, комментарии и прочий нерелевантный функционал до появления работающего редактора.
- Заменять согласованный PDF current-view экспорт универсальным «вывести всю базу в PDF».

## Контрольный визуальный сценарий заказчика

Открыть `Главная` -> виден проект с четырьмя этапами, множеством процессов и блоком занятости. Выбрать процесс «Разработка персонажей» -> справа детали, внутри откроются минимум три задачи. Выбрать соседний процесс -> первый остаётся открыт. Увеличить масштаб + -> задачи визуально шире, даты не изменились. Поставить шаг 1 неделю -> сетка и прилипания стали недельными. Включить выходные -> бледно-зелёные полосы. Навести на задачу -> соответствующий художник подсветился внизу. Ухватить маленькую ручку процесса и сдвинуть +1 неделю -> его задачи сдвинулись вместе. Изменить правую границу одной задачи -> процесс при необходимости расширился. Сделать Undo -> восстановился предыдущий результат. Экспортировать PDF -> текущий вид с раскрытыми процессами и видимым диапазоном отображён без панелей управления.

Эти шаги последовательно реализуются в V1–V6, но **визуально узнаваемая сцена должна быть готова уже в V1**.
