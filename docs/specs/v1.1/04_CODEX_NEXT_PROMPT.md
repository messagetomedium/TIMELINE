# Следующее задание Codex — исправить календарь и рабочую область (V1.1)

Работаем в **существующем** репозитории `messagetomedium/TIMELINE`, продолжаем `main` после реализованного визуального V1. Не создавай новый репозиторий, не начинай проект заново и не заменяй приложение готовой Gantt-библиотекой без доказанной необходимости.

**Прочитай в репозитории** `README.md`, `src/features/timeline/TimelineWorkspace.tsx`, `CalendarLayers.tsx`, `PerformersSection.tsx`, `TimelineBar.tsx`, `useTimelineGesture.ts`, `src/domain/timeline.ts`, `src/application/timelineLayout.ts`, `src/styles/timeline.css`, текущие тесты и `docs/specs/*`. Применяй новый приложенный документ **`01_NEXT_TZ_CALENDAR_V1_1.md`** как актуальный контракт этого этапа, а **`02_ARCHITECTURE_DELTA.md`** — как рекомендации по устройству кода. **`03_ROADMAP_AFTER_V1_1.md`** показывает будущие работы, но в этой итерации НЕ реализуй следующие этапы.

**Причина задачи:** текущий `TimelineWorkspace` подгоняет весь год к ширине экрана, из-за чего неделя становится полоской шириной около 17–25 px, а месяцы и дни почти невозможно читать. Пользователь не воспринимает сцену как рабочий календарь с таймлайнами. Проблему нельзя решать одной сменой цветов/шрифта. Нужна новая компоновка календарной шкалы и стартовый рабочий масштаб при сохранении уже работающих drag/resize/раскрытий.

## Что сделать именно сейчас

1. Исправь стартовую камеру: не использовать fit-year по умолчанию; установить рабочий масштаб с разборчивыми недельными колонками, якорем на сегодня, если дата относится к проекту, иначе к началу активных работ. Сохрани логическую позицию при resize.
2. Переделай календарный верх: реальная двухуровневая шапка МЕСЯЦ/ГОД + ЯЧЕЙКИ выбранного шага (день, 2/3 дня, неделя, 2 недели, месяц). Дата и ширина колонок из календарной арифметики, а не условной равномерной сетки. Убери статическое `2026 — 2027`.
3. Сделай полупрозрачные вертикальные календарные линии и подсветку выходных, которые точно совпадают через header, stage bands, основную производственную сцену и нижние полосы исполнителей. Отдельно выдели текущий день и границы этапов.
4. При необходимости введи корректную фиксированную левую колонку заголовков секций, без перекрытия таймлайна и без смещения pointer-геометрии. Синхронизируй все слои через одну камеру и реальную ширину временного viewport.
5. Добавь кнопки **Сегодня** и **Весь проект** в нижнюю рабочую панель. Отдельно оставь zoom +/- и выбор snap/grid. Zoom и snap остаются независимыми.
6. Добавь редактирование даты линии этапа прямым вводом наряду с существующим drag за круглый маркер.
7. Сохрани без регрессий: двойной клик названия, drag только за ручку, resize за края, раскрытие нескольких процессов, перенос детей с родителем, автоматическое расширение родителя задачей, запрет коллизий в одной строке, hover-связь с исполнителями.

## Приёмка — обязательная

- Рабочий экран 1440×900: видно 2 соседних месяца и минимум 6 читаемых недельных столбцов, а не весь год; на экране есть полосы процессов и вложенных задач, правый инспектор и нижняя занятость.
- Показать два режима screenshots: рабочий масштаб и «Весь проект». Должна быть явная визуальная разница.
- Продемонстрировать 6 шагов сетки, переключатель выходных, pan, zoom, Сегодня, редактирование этапной даты и существующие жесты. Изменение вида НЕ меняет даты задач.
- Проверить совмещение календарных границ в header, основном и нижнем блоках с точностью до 1 CSS px на каждой контрольной дате после pan/zoom; протестировать переходы месяцев.
- Обновить Playwright и unit-тесты по этим кейсам; выполнить `npm run lint`, `npm run build`, `npm run test`, `npm run test:e2e`. Если часть нельзя запустить — указать настоящую причину, не выдумывать успешные проверки.
- Сохранить настоящие screenshots браузера для 1440×900 (рабочий и fit-project) и 1920×1080 в `docs/screenshots/`. В отчёте дать пути к снимкам, перечислить изменённые файлы и всё, что ещё НЕ реализовано.

**Не делай пока** Supabase, AI, авторизацию, локальную БД, портфолио, PDF, всю логику multi-select/undo и полное редактирование людей — это следующие задачи. Не рисуй декоративные неработающие кнопки. Для этой итерации важнее реально удобная календарная сцена, чем количество реализованных пунктов roadmap.

Работай в отдельной ветке `feat/calendar-ux-v1-1`, сохрани существующие тесты и полезную архитектуру. Изменения в `main` и публикация допустимы после проверки. В финальном отчёте различай «прошли тесты», «сделано в коде», «запушено», «опубликовано».
