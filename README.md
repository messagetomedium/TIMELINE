# Таймлайн

Новый браузерный редактор производственных планов. Сейчас реализован **Slice 0 и минимальный доменный каркас Slice 1**, а не весь редактор из [ARCHITECTURE.md](ARCHITECTURE.md) и [CODEX_SPEC.md](CODEX_SPEC.md).

Приложение сразу открывает обзор проектов на русском языке. Вход, сервер приложения, Supabase, ChatGPT, аккаунты и настройка сети не нужны. Демо включается только кнопкой «Показать демо-проект», затем карточка открывает сводку только для чтения. Перезагрузка возвращает пустой обзор: сохранения и реальных пользовательских проектов пока нет.

## Запуск

Нужен Node.js **24.19.0** (см. `.nvmrc`) и npm. При наличии nvm: `nvm install && nvm use`.

Все команды выполняются в корне этого репозитория:

```sh
npm install
npm run dev
```

Зависимости нужны только для установки; приложение не обращается к внешним сервисам. Для установки точно по сохранённому lockfile в CI или чистом окружении используйте `npm ci`.

## Проверки

```sh
npm run lint
npm run build
npm run test
npx playwright install --with-deps chromium
npm run test:e2e
```

`build` сначала выполняет strict typecheck исходников, конфигурации и тестов (`tsc -b`), затем сборку Vite. `test` — однократный запуск Vitest; `test:watch` — наблюдение. Playwright сам запускает и останавливает `vite preview`, поэтому перед `test:e2e` нужна актуальная сборка.

В этой облачной среде уже установлен системный Chromium. Проверенный вариант без дополнительной загрузки браузера:

```sh
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

На обычной машине предпочтителен Chromium, установленный Playwright командой выше. Smoke-тесты проверяют старт без ошибок консоли и внешних запросов, включение фиксированного демо, сводку, возврат/перезагрузку без создания IndexedDB или localStorage, клавиатуру и узкий экран. Проверка выполнена в Chromium; остальные браузеры пока не покрыты. CI-конфигурация — `.github/workflows/ci.yml`; её запуск на GitHub отдельно не подтверждён.

## GitHub Pages

Workflow `.github/workflows/pages.yml` проверяет и собирает приложение, затем публикует `dist` при push в `main` или ручном запуске. В репозитории **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**. Workflow не требует дополнительных секретов: он использует стандартный `GITHUB_TOKEN` с `pages: write` и `id-token: write` только в задании публикации.

Ожидаемый адрес для этого репозитория — `https://messagetomedium.github.io/TIMELINE/`. Наличие workflow само по себе не подтверждает, что сайт опубликован. Статус доступен в Actions → «Публикация GitHub Pages». Vite использует относительные URL ресурсов (`base: './'`), чтобы сборка работала как в корне, так и по пути проекта Pages.

Для smoke-проверки пути проекта локально можно скопировать `dist` в `dist/TIMELINE` и запустить `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4173/TIMELINE/ npm run test:e2e`. После проверки вложенную копию нужно убрать перед публикацией: артефакт Pages должен содержать только исходный `dist`.

## Реализовано

- Vite + React + TypeScript strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, ESLint с типовой информацией и ограничением направления импортов, Vitest, Playwright, npm lockfile, CI-рецепт.
- Разделение `domain` → `application` → UI/адаптеры; точка композиции в `main.tsx`. Токены оформления, русский обзор и два простых экрана без временной оси.
- Брендированные UUID и date-only типы, календарные дни/месяцы, понедельник как начало недели, включение/пересечение и смещение полуоткрытых интервалов.
- Строгие runtime-схемы и readonly-типы Project, StageMarker, Lane, Process, Task, Person, Assignment, ViewPreferences и версионированный ProjectDocument. Проверяются связи, уникальность ID, интервалы, дорожки и назначения. Все шесть статусов заданы точно по спецификации.
- `ProjectRepository` как интерфейс атомарного хранения с ожидаемой ревизией, без реализации и утверждений о синхронизации.
- Отдельное opt-in демо с фиксированными ID и датами: два процесса, три задачи, две датированные отметки, человек и назначения. Фикстура не является сидером и никогда не пишет в хранилище.
- Тесты календаря (включая DST, високосные годы и границы диапазона), runtime-схем, ссылочной целостности, коллизий, статических брендов и browser smoke.

## Не реализовано

CommandBus, undo/redo, IndexedDB/Dexie, миграции базы, autosave и CRUD/дублирование проектов, JSON backup/import. Нет интерактивного таймлайна, drag/resize, snap, камеры/зума, инспектора, панели исполнителей, портфолио и PDF. Схема версии DTO уже есть; миграций ещё нет. Сохранение, работа между устройствами и серверная синхронизация не имитируются. Zustand, Dexie и роутер пока не требуются и не установлены.

## Структура

```text
src/
  domain/                # даты, ID, сущности, схемы и тесты
  application/           # ProjectRepository и чистые запросы
  infrastructure/demo/   # фиксированные проверяемые данные
  features/projects/     # обзор и сводка только для чтения
  app/                   # оболочка и состояние экрана
  styles/                # токены и оформление
  main.tsx               # композиция приложения
tests/e2e/               # smoke-тесты браузера
docs/adr/                # решения и временные допущения
```

[ADR 0001](docs/adr/0001-foundation-scope.md) описывает границы каркаса, in-memory демо и отсутствие URL-маршрутизации. [ADR 0002](docs/adr/0002-calendar-and-schema.md) фиксирует календарную семантику, месячное ограничение дня, UUID, ревизии и временную трактовку групп назначений.
